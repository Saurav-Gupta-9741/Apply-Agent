## 1. Product rules — breaking any of these means the work is rejected

1. Never fill a wrong value. When unsure, leave the field and ask the user.
2. No anti-bot evasion: no fake mouse moves, fake keystroke streams, random human-like delays. (Fixed small pauses for page reliability are OK — see src/shared/pacing.ts.)
3. Never solve or bypass CAPTCHAs.
4. Never automate hands-off platforms (LinkedIn, Naukri, Indeed, Glassdoor, foundit, Wellfound, Instahyre, Internshala, iimjobs/Hirist, Cutshort, ZipRecruiter, Dice, Shine, apna). Reading a tab's title/URL to save a job is allowed; filling is not.
5. Never tick consent boxes automatically (src/shared/consent-review.ts is the only path: one box per user click).
6. Never fill or store ID numbers, card numbers, CVV, OTP, passwords, signatures (src/content/classify.ts SECRETS/identity).
7. Never invent facts about the user. Every filled value must come from the profile, a saved answer, or literal resume text the user confirmed.
8. Personal data never leaves the browser. No telemetry, no new network calls, no remote code.
9. No accounts/login in v1. No new prices or perks — prices come only from server/wrangler.toml and site/site.config.json (Pro ₹149/$9 30 days, Founder ₹2999/$49 10 years).
10. Do not hardcode any real person's data (the earlier hardcoded Google Drive resume link was a serious bug).

## 2. Work rules

- Never edit an existing test to make it pass, unless the test pins a WRONG fill — then say so in the report with the reason.
- Never weaken a safety guard (honeypot detection, SECRETS, NOT_A_FACT, OTHER_PERSON, isApplicationPage, busy lock, hands-off).
- Every new rule gets a test with an exact expected value (`toBe`/`toEqual`). No hollow assertions (`toBeDefined`, `not.toBe("fill")`, `if (x) expect…`, ranges that can't fail).
- No test data generated by the code under test. No "hand-labelled" claim unless a human labelled it.
- Commit messages and reports must be true. Don't claim "retrained" unless model files changed; don't call 167 tests "1,000 agents".
- Before every commit: `npx tsc --noEmit`, `npx vitest run` (all), `npm run build`. Before finishing a task: `npx playwright test --workers=1` (all must pass; fix flakes properly, don't skip).
- After test runs, `git checkout -- reports/automation-baseline.json reports/scorecard.json` unless you meant to change them.
- One commit per task. Push to `origin phase3` only — never push to `main`.

## 3. Tasks, in order

### Task 1 — Resume → profile import (biggest gap vs Simplify) · ~1 day
- `src/shared/resume-parse.ts` (start from the WIP branch version): `parseResume(text)` → suggestions `{field, value, confidence, sourceLine}` for name, email, phone (reuse `src/content/phone.ts`), city/country (`src/shared/countries.ts`), LinkedIn/GitHub/portfolio, education (degree, institution, discipline, year, CGPA/% incl. "CGPA 8.4/10"), work history (company, title, dates, current), total experience computed from dates (show as computed; ask when dates are missing), skills (`src/shared/techterms.ts`), languages.
- Text from PDF via `pdfjs-dist` bundled locally (no CDN; MV3 CSP is `'self' 'wasm-unsafe-eval'`), DOCX via `word/document.xml` (DecompressionStream), plus a "Paste resume text" box.
- UI `src/sidepanel/resume-import.ts`: review list; a box is pre-ticked only if confidence is high AND the profile field is empty; existing values are never overwritten unless the user ticks "replace"; "Save selected".
- Tests: the 7 resumes in `test/fixtures/resumes/` + at least 2 real-looking PDFs and 1 DOCX; exact expected outputs; a test that no value appears that isn't in the text. e2e: paste → review → save → existing value untouched.
- Done when: all fixture fields exact, 0 invented values, bundle size increase reported.
